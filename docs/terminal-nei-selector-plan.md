# XTracer 终端 Block / Ore 选择器方案

## 1. 目标与边界

在手持终端 GUI 中用可检索目录取代手动输入 `/xtracer block` 和 `/xtracer ore`。目录分为 **Block** 与 **Ore** 两个分页：Block 页选择具体可放置方块及变体；Ore 页通过复选框多选 Ore Dictionary 名称。扫描仍由服务端执行，命令保留为兼容和调试入口。

本方案不依赖 NEI。XTracer 使用 Minecraft/Forge 注册数据、Item/Block 关系和 Ore Dictionary 自行构建目录。NEI 既不是运行时依赖，也不是目录数据源；以后若要做配方/用途等独立增强，再单独评估可选集成。

## 2. GUI 交互

### 2.1 公共区域

- 顶部两个分页：`Block`、`Ore`。
- 每页有独立搜索框，输入变化后过滤当前页缓存结果。
- 目录采用图标网格、分页/滚动和 hover tooltip；只渲染当前可视条目。
- 底部保留当前目标摘要、搜索半径、Get Drops 开关、Ray Select 和 Scan 操作。
- GUI 目录选择只形成待提交状态；收到服务端确认后才显示为已应用设置。

### 2.2 Block 页

只显示可由玩家放置的方块，不显示仅能手持、但不能映射到可放置方块的物品。

- 从 `Block.blockRegistry` 枚举注册方块，再查找其对应的物品表示（1.7.10 中通过 `Item.getItemFromBlock` / 对应 ItemBlock 关系）。
- 排除空气、无有效注册名、没有可用放置物品表示的条目。
- 列表条目以 `registryName + metadata` 唯一标识。同一注册方块有多个可选 ItemStack/meta 时分别显示，使玩家可以选择具体变体。
- 优先通过对应 Item 的 `getSubItems` 收集其公开的可选变体；对无法提供子项的可放置方块使用明确的默认变体。不得简单地对所有 Block 无条件生成 0..15 条目，因为多数 metadata 并不一定是有效或可选择变体。
- 点击一项后发送规范化的 `BLOCK` 目标：注册名和 metadata。服务端检查方块存在、metadata 合法并可映射到方块，再更新目标。
- 搜索覆盖本地化显示名、注册名和 metadata；目录缓存建立后不在每次按键时重新枚举注册表。

首版的“可放置”按物品栏中存在对应可用 ItemStack、且该 ItemStack 能映射回该方块定义。若某模组方块只能通过特殊机器/结构生成而没有普通放置物品，它不属于本页范围。

### 2.3 Ore 页

显示有效的 Ore Dictionary 名称清单，每个名称是一项复选框，可多选。

- 名称来自 Forge `OreDictionary` 已注册名称；仅显示确实存在且有非空条目的矿辞。
- 搜索覆盖矿辞名称和可选的代表性条目名称。
- 每行可以显示矿辞名称、代表性图标和匹配条目数量；一个矿辞可能对应多种物品或方块。
- 复选框集合是当前完整 Ore 目标集合。勾选/取消后以集合方式提交，允许一次选择 `oreCopper`、`oreIron` 等多个目标。
- 服务端检查每个矿辞名称存在且有内容，再整体应用目标集合；任何无效名称应返回明确失败，不应悄悄应用部分集合。
- 空集合表示没有 Ore 目标，不应被解释为“匹配全部矿物”。

## 3. 扫描语义

### 3.1 Block 模式

当前 Block 页允许单个 `registryName + metadata` 目标。服务端在扫描范围内比较方块注册名和实际 metadata，命中后每个世界坐标最多记录一次。

### 3.2 Ore 多选模式

玩家选中多个矿辞时，扫描语义是 **OR**：

> 如果一个世界方块的掉落物带有任意一个已选 Ore Dictionary 名称，该方块就命中。

举例：选择 `oreCopper` 和 `oreIron` 后，扫描器寻找掉落物属于任一所选矿辞的方块矿石。需要检查方块掉落物并提取其 Ore Dictionary IDs/名称；比较时沿用当前项目对 `raw` 前缀和小写名称的规范化规则，确保 UI 选择值、命令现有值和扫描值一致。

多选必须修正现有扫描代码的重复计数风险：当一个方块的掉落物同时匹配多个已选矿辞时，该坐标只加入结果一次。命中一个目标后跳出目标循环，或通过坐标集合去重。扫描结果数量、`FoundBlocksMessage` 高亮坐标和可选 Get Drops 处理必须共享去重后的坐标列表，确保每个方块最多处理一次。

配置由单个矿辞扩展为玩家各自的矿辞集合。旧版单值/单元素列表配置在升级后仍能读取；现有 `/xtracer ore <name>` 设置为只有该名称的单元素集合，不破坏命令兼容性。

## 4. 目录构建与检索

目录在客户端第一次打开选择器时构建并缓存，搜索只过滤缓存结果。

- Block 数据源：Forge/Minecraft Block 注册表及其 Item 表示、Item 子项和本地化名称。
- Ore 数据源：`OreDictionary` 名称及其条目 ItemStack。
- 不经网络发送完整目录，也不把客户端 ItemStack、NBT 或对象引用当成服务端目标。
- 搜索文本统一转小写，支持显示名、注册名、metadata 和矿辞名包含匹配。
- 目录按稳定 key 去重：Block 为 `registryName + metadata`；Ore 为规范化矿辞名称。
- 对损坏或无法读取显示信息的单个条目跳过并记录调试日志，不让一个坏条目阻断整个 GUI。
- 所有条目可分页；GUI 只绘制当前页/可见区域，避免 GTNH 大型注册表下整表重绘造成卡顿。

## 5. 网络与服务端验证

GUI 仅发送小型规范化请求。服务端始终以消息上下文中的玩家、服务端注册表和服务端配置为准。

### 5.1 Block 目标请求

```text
action = SET_BLOCK_TARGET
registryName
metadata
```

服务端校验注册名、方块存在性、metadata 范围和目标配置后再保存。

### 5.2 Ore 集合请求

```text
action = SET_ORE_TARGETS
count
oreName[0..count)
```

服务端限制集合数量和每个名称的字节长度；只接受已注册且有内容的矿辞。重复名称规范化去重。超过限制、存在无效名称或数据包格式异常时拒绝整次更新并反馈原因。

### 5.3 通用要求

- 不接受客户端 UUID、扫描坐标、权限或任意 Java 对象。
- 扫描中心只从服务端玩家实体取得。
- GUI 客户端不直接修改 `Config`；提交后通过服务端确认更新界面。
- Scan 和 Get Drops 继续由服务端执行；Get Drops 的破坏性语义必须在 GUI 中明确呈现。

## 6. 掉落及扩展功能边界

核心优先于边缘特判，按通用能力建模，不按具体方块注册名硬编码。

- 默认扫描只查找并高亮，不破坏方块。
- Get Drops 是玩家显式开启的高风险操作；不为首版处理一般玩家能够规避的容器内容丢失问题。GUI 清楚说明启用后会生成掉落并移除命中的方块。
- 精准采集作为后续独立开关；需要先确认 1.7.10/GTNH 的工具、附魔及掉落 API 能否可靠模拟玩家采集，不承诺未经验证的普适行为。
- GTNH 永久性作物未来单独设计“只收割、不破坏”逻辑，基于成熟/作物行为能力，不按 A 方块/B 方块写名单；本阶段不实现。
- 容器库存、机器状态保留暂缓；只有明确出现实际需求时，才基于通用 TileEntity/库存能力设计。
- 普通非方块物品不进入 Block 页。未来若有扫描掉落实体等需求，应新增清楚定义的目标模式，不混入方块扫描语义。

## 7. 分阶段实现

### 阶段 A：Block 页

1. 实现客户端 Block 注册表目录构建、Item 变体枚举、缓存和搜索。
2. 实现图标网格、hover 信息和分页。
3. 点击方块变体后通过 C2S 请求设置注册名和 metadata。
4. 服务端验证并更新 Block 目标；保留 `/xtracer block`。

### 阶段 B：Ore 多选页

1. 构建 Ore Dictionary 名称和代表性图标目录。
2. 实现复选框、多选、搜索、分页和已选数量/名称摘要。
3. 将玩家配置扩展为 Ore 名称集合，并兼容旧配置和命令入口。
4. 服务端整体校验集合后应用。
5. 更新扫描匹配为任一目标命中，并确保结果坐标唯一。

### 阶段 C：操作闭环与测试

1. 确认重新打开 GUI 可正确显示服务端已保存选择。
2. 测试不同玩家选择彼此隔离。
3. 测试一个方块匹配多个所选矿辞时只计数、掉落和高亮一次。
4. 测试大目录搜索、分页和空结果性能。
5. 测试非法注册名、metadata、Ore 名称、空集合和超大网络集合被正确拒绝。

## 8. 验收标准

- XTracer 的编译、运行和基础目录完全不依赖 NEI。
- Block 页只出现有普通可放置物品表示的方块，不出现仅能手持的非方块物品。
- 具有多个可选 ItemStack/meta 的方块可以选择具体变体。
- Ore 页显示 Ore Dictionary 名称复选框，支持多选和取消选择。
- 同时选择 `oreCopper`、`oreIron` 时，任意一种目标命中的矿石方块都会被发现。
- 同一方块命中多个已选矿辞时扫描结果只有一个坐标，Get Drops 不重复执行。
- 服务端重新验证全部目标；客户端不能通过目录对象直接驱动世界修改。
- `/xtracer block` 和 `/xtracer ore` 继续可用，其中 ore 命令等价于设置单个 Ore 复选目标。
- GUI 搜索、分页、图标和 tooltip 在 GTNH 大型物品/方块集合下保持可用。

## 9. 已确定结论

> **选择器仅有 Block 与 Ore 两页，基础功能不依赖 NEI。Block 页枚举可放置方块及其可选 metadata/物品变体，排除只能手持而不能作为方块放置的物品。Ore 页以 Ore Dictionary 名称为复选项，允许多选；扫描时按 OR 语义寻找掉落物匹配任一所选矿辞的方块，并保证每个坐标只处理一次。目录和搜索由客户端缓存，所有目标及扫描操作由服务端校验和执行。**
