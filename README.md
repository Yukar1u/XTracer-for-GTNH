# XTracer

XTracer 是面向 **Minecraft 1.7.10 / Forge** ，并且处理逻辑专门对GTNH做兼容的方块扫描与物品收容模组。通过手持终端选择目标、扫描附近方块，并将产生的掉落物远程写入绑定的超空间量子收容节点。
使用 GTNH 构建工具链，但不依赖 GregTech 或其他mod

**注意**: 该模组效果极其暴力，旨在帮助玩家跳过GTNH中的找矿、挖矿过程，如果使用该模组游玩，会破坏GTNH原本的平衡性。该模组的物品并未设置配方，需要玩家作弊获取。

## 功能

- **目标扫描**：按方块、元数据或矿物词典目标匹配，扫描结果在世界中高亮。
- **掉落与远程收容**：开启掉落后移除匹配方块；可将物品按节点规则分配到绑定容器。
- **大数量存储**：按物品注册 ID、damage 和 NBT 区分库存，每种物品使用 `long` 记录数量。
- **存储界面**：每页 9×5，共 45 种物品，支持整个库存搜索、分页、滚轮翻页和点击取出。
- **容器输出**：所有面支持通过库存接口提取，禁止通过普通库存接口插入。

## 安装

运行环境：

| 项目 | 版本 |
| --- | --- |
| Minecraft | 1.7.10 |
| Forge | 10.13.4.1614 |
| 字节码版本 | Java 8 |

将 `x_tracer-1.5.2.jar` 放入实例的 `mods` 目录。多人游戏需要客户端与服务端同时安装，且使用相同版本。Java 的实际启动配置请遵循所用整合包的要求。

## 获取物品

当前没有注册合成配方。mod物品可在创造模式的工具页签中找到，也可使用原版命令获取：

```text
/give <玩家名> x_tracer:xtracer_terminal 1
/give <玩家名> x_tracer:xtracer_container 1
```

命令需要服务器授予相应权限。终端和容器都注册在原版创造模式的“工具”页签中。

## 快速开始

1. 手持 **XTracer 手持终端**，右键打开界面。
2. 在“方块”或“矿辞”页选择目标，点击“保存目标”。方块支持 **Alt + 点击**展开变体，矿辞支持多选。
3. 输入扫描半径并点击“应用”。默认半径为 **10 格**，可设置为 **1–100 格**。
4. 保持掉落关闭，点击“扫描”或在手持终端时按 **X**，检查高亮结果。
5. 需要收集物品时，开启“掉落”再扫描。**开启掉落后会移除匹配方块**，建议先确认目标与半径。

扫描范围以玩家所在方块位置为中心，按球形距离筛选。快捷键可在游戏控制设置中调整。

“视线选择”可用于选择当前指向的目标。方块目标格式为 `modid:block@meta`；特殊掉落物目标格式为 `drop:modid:item@damage`。

## 远程收容

1. 放置超空间量子收容节点。
2. 手持终端，潜行右键节点完成绑定；也可使用终端中的“绑定视线容器”按钮。
3. 右键节点打开存储界面，在“路由设置”中填写名称、接收规则和排除规则，点击保存。
4. 在终端中同时开启“掉落”和“远程输入”，然后扫描目标。

每个终端最多绑定 **16 个节点**。绑定或解绑时需要距离目标中心不超过 **8 格**。绑定记录包含维度、坐标和节点身份；原位置的节点被替换后需要重新绑定。

远程路由可以访问其他已加载维度中的节点。一个物品匹配多个可用节点时，会在这些节点间平均分配，余数按节点顺序分配。未匹配到节点的物品会作为普通掉落物生成在玩家附近。

节点不可用或写入失败时，聊天消息会显示具体原因。含库存或其他方块实体数据的源方块批次会跳过远程写入，物品按普通掉落方式交付。

## 路由规则

规则采用**不区分大小写的字面子串匹配**，支持注册 ID、`ID@damage`、未本地化名称及显示名称。远程扫描使用发起客户端提供的本地化物品名称，因此可以填写中文名称。

- **接收列表为空**：接收所有未被排除的物品。
- **接收列表非空**：至少命中一条接收规则才接收。
- **排除规则优先**：命中任意排除规则即拒收。
- 多条规则使用 `,`、`;`、`|`、`，` 或 `；` 分隔。
- 接收与排除列表各最多 **32 条**，每条最多 **64 个字符**；容器名称最多 **32 个字符**。

示例：

| 接收规则 | 排除规则 | 含义 |
| --- | --- | --- |
| 留空 | 留空 | 接收全部物品 |
| `minecraft:` | 留空 | 接收注册 ID 或名称匹配文本中含 `minecraft:` 的物品 |
| `铁,铜` | 留空 | 接收显示名称或其他匹配文本中含“铁”或“铜”的物品 |
| 留空 | `minecraft:cobblestone` | 排除圆石，其余物品接收 |

规则不支持通配符、正则表达式或布尔表达式。由于是子串匹配，填写 `ID@damage` 也不代表严格相等匹配。**路由规则不匹配矿辞名称**；终端的矿辞目标选择与库存搜索是另外的功能。

只有节点所有者可以修改名称和规则。普通玩家在访问距离内可以打开节点并取出物品，所有者设置不构成库存访问锁。

## 存储界面与自动化

- 每页显示 **45 种物品**，搜索在整个节点库存中执行后再分页。
- 搜索支持本地化名称、注册 ID 和矿辞名称；名称分批读取，大库存可能需要等待。
- 鼠标位于存储格子区域时，可使用滚轮翻页。
- 左键点击物品，取出最多一组：上限为 **64 件**，同时遵守物品自身最大堆叠数。
- 取出物品优先放入背包，背包放不下的部分掉落在玩家附近。
- 库存变化后，过期的取出请求会被拒绝；刷新列表后重新点击即可。

节点实现 `ISidedInventory`，所有面提供输出槽，禁止插入。可供支持该库存接口的漏斗或管道提取；具体自动化模组的兼容情况需在所用整合包中验证。

每种完整物品键的数量上限为 `Long.MAX_VALUE`，即 **9,223,372,036,854,775,807**。源码未设置固定物品种类数上限，实际可用规模仍受内存、存档大小和同步性能影响。

仍有物品的节点不能通过正常玩家拆除流程拆除，请先取空库存。

## 命令

```text
/xtracer cur
```

显示当前目标、匹配模式、扫描半径及掉落设置。普通玩家可使用，该命令需要由游戏内玩家执行。其他设置通过终端 GUI 完成。

## 从源码构建

项目使用 **Gradle 8.13 Wrapper**、GTNH convention 插件及 Jabel。构建环境使用 Amazon Corretto 1.8.0_462 (Java 8)。首次构建需要联网下载依赖。

Linux / macOS / Git Bash：

```bash
./gradlew build
```

Windows 命令提示符：

```bat
gradlew.bat build
```

默认构建版本来自 Git 标签与提交信息，未提交改动可能使版本带有 `dirty` 后缀。构建当前 1.5.2 发布包时，可显式覆盖版本：

```bash
# Linux / macOS / Git Bash
VERSION=1.5.2 ./gradlew build
```

```powershell
# Windows PowerShell
$env:VERSION = "1.5.2"
.\gradlew.bat build
```

产物位于 `build/libs/`，安装时使用 `x_tracer-1.5.2.jar`，不要使用 `sources` 或 `dev` 包。

`VERSION` 环境变量控制构建版本和生成元数据；`MyMod.java` 的 `@Mod` 版本目前为硬编码。发布新版本时，需要同时更新源码中的版本，确保归档、生成元数据与游戏内版本一致。版本覆盖不会提交工作区改动，`git show` 仍显示已提交的内容。

## 开发结构

| 路径 | 职责 |
| --- | --- |
| `src/main/java/com/yukar1n/x_tracer/client/gui/` | 终端与存储界面 |
| `src/main/java/com/yukar1n/x_tracer/container/` | 玩家库存槽及容器交互逻辑 |
| `src/main/java/com/yukar1n/x_tracer/network/` | 客户端与服务端消息 |
| `src/main/java/com/yukar1n/x_tracer/server/` | 扫描、掉落与远程路由 |
| `src/main/java/com/yukar1n/x_tracer/storage/` | 物品键、数量存储、规则及终端绑定 |
| `src/main/java/com/yukar1n/x_tracer/tileentity/` | 节点库存与持久化 |
| `src/main/resources/assets/x_tracer/lang/` | 中文与英文语言文件 |
